Difference Between Local Variable and Global Variable
1. Local Variables:
These variables are declared inside a method, constructor, or block and can only be accessed within that specific scope.
They are not accessible outside the method in which they are declared.
Memory for local variables is allocated when the method is called and deallocated once the method execution is completed.
They must be initialized before use; otherwise, the compiler will throw an error.
Local variables do not have default values—they must be explicitly assigned a value before being used.
They are stored in the stack memory, making them efficient in execution.
They cannot have static or access modifiers (like public, private, or protected).
2. Global Variables:
These variables are declared outside any method, typically within a class, and can be accessed by any method in the same class and even from other classes using the class name or an instance of the class.
They are classified into two types:
Static Global Variables: Shared among all objects of the class and belong to the class itself. They can be accessed using ClassName.variableName.
Non-Static Global Variables: Unique to each object of the class and require an instance to access (objectName.variableName).
Global variables do not require explicit initialization; the compiler assigns a default value if not initialized (e.g., 0 for integers, null for objects, false for booleans).
They are stored in the heap memory (for non-static global variables) or method area (for static global variables).
Unlike local variables, they can have access modifiers (public, private, protected).

 

| Feature           | Local Variable | Global Variable |
|------------------|--------------|---------------|
| **Declared In**  | Inside a method or block | Inside a class but outside methods |
| **Scope**        | Limited to the method/block | Accessible by all methods in the class |
| **Access Outside Class?** | ❌ No | ✅ Yes (using class name or object) |
| **Types**        | No specific types | Static and Non-Static |
| **Default Value** | ❌ Not provided (must initialize) | ✅ Provided by the compiler |
| **Stored In**    | Stack memory | Heap (non-static) / Method area (static) |
| **Lifetime**     | Exists only during method execution | Exists as long as the object/class is loaded |
| **Access Modifiers** | ❌ Not allowed | ✅ Allowed (`public`, `private`, etc.) |
| **Can Be Static?** | ❌ No | ✅ Yes |

Difference Between Static and Non-Static Members
a. Static Members
Single Copy in Memory: Static members belong to the class rather than any specific object, meaning only one copy exists, shared among all instances of the class.
Stored in the Static Pool Area: They are loaded into a special memory area known as the static pool when the class is first loaded.
Access Without Object Creation: Static members can be accessed using the class name itself (ClassName.staticMember) or through an object, but using the class name is recommended.
Lifetime: Static members exist as long as the class is loaded in memory. They are destroyed only when the program ends or the class is unloaded.
Efficient Memory Usage: Since only one copy is maintained, memory consumption is optimized.
Common Examples: Static variables, static methods, and static blocks in Java.
Cannot Access Non-Static Members Directly: Since static members belong to the class and not an object, they cannot directly access non-static (instance) members unless an object reference is used.

b. Non-Static Members
Multiple Copies in Memory: Each object of the class gets its own separate copy of non-static members.
Stored in the Object Area: These members are stored in the heap memory within the object area, where each object has its own memory allocation.
Accessed Through Objects: Non-static members can only be accessed through an instance (object) of the class (objectName.nonStaticMember).
Lifetime: They exist as long as the object exists. When an object is destroyed (e.g., by the garbage collector in Java), its non-static members are also removed from memory.
Uses More Memory: Since every object has a separate copy of non-static members, memory consumption is higher if many objects are created.
Can Access Both Static and Non-Static Members: Unlike static members, non-static members can access both static and non-static variables/methods within the class.
